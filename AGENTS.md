# AGENTS.md

Purpose: concise, automation-friendly guidance for coding agents. For human-focused onboarding and full details, see [README.md](README.md).

## Scope

- This repository is a Docusaurus 3 documentation site.
- Canonical scripts live in [package.json](package.json). Don’t duplicate command logic here.

## Environment

- Node: see engines in [package.json](package.json) (`"node": ">=20.0"`).
- Package manager policy: use npm only.
  - Keep one lockfile (`package-lock.json`) per npm project: the site at the root, and the Remotion project in `videos/`.
  - If a `yarn.lock` exists, remove it to avoid conflicts.

## Core commands (reference only)

Delegated to package.json scripts—invoke via npm:

- Dev: `start`
- Build: `build`
- Preview: `serve`
- Clear caches: `clear`
- Type-check: `typecheck`

Examples (npm):

```bash
npm ci
npm start
npm run build
npm run serve
npm run clear
npm run typecheck
```

The site ships as a Docker image served by nginx, see [README.md](README.md).

## Quality gates for automation

- Typecheck must pass:

```bash
npm run typecheck
```

- Production build must succeed (onBrokenLinks=throw; onBrokenMarkdownLinks=throw via config/markdown hooks):

```bash
npm run build
```

- Optional: preview built site locally:

```bash
npm run serve
```

## Site URL

`docusaurus.config.ts` reads `url` from the `DOCS_URL` environment variable, defaulting to `https://docs.agentic.6022.io`. It is a build-time variable (Docusaurus does not load `.env` files), and it drives the absolute URLs written into `llms.txt` and `sitemap.xml`.

```bash
DOCS_URL=http://localhost:3000 npm run build
docker build --build-arg DOCS_URL=https://staging.example.com -t docs .
```

## LLM-readable output

`npm run build` also emits, via [docusaurus-plugin-llms](https://github.com/rachfop/docusaurus-plugin-llms) (see `plugins` in [docusaurus.config.ts](docusaurus.config.ts)):

- `/llms.txt` — [llmstxt.org](https://llmstxt.org) index: every page as an absolute link plus a short excerpt, in sidebar order: Docs, Teams, then Reference.
- `/llms-full.txt` — the whole corpus in one file.
- `/docs/**/*.md` — per-page markdown mirroring the site routes, e.g. `/docs/intro.md`. Prefer these over scraping the HTML.

Page excerpts in `llms.txt` are taken from the `description` frontmatter field when present, otherwise from the first lines of the body — add `description:` to a doc's frontmatter to control what agents see.

## Authoring boundaries

- Layout: three navbar tabs, one sidebar each, all in [sidebars.ts](sidebars.ts):
  - **Docs** (`docs` sidebar): `intro.md`, `quickstart.md`, `concepts/` (runtime-neutral, no tabs), `guides/` (task pages with runtime tabs), Runtimes = `agent/` (the 6022 Agent) + `runtimes/` (Hermes, OpenClaw setup pages, agent skills), `troubleshooting.md`, `examples.md`, `philosophy.md`.
  - **Teams** (`teams` sidebar): `teams/**`, the orchestrator and Slack.
  - **Reference** (`reference` sidebar): `developers/**`, autogenerated.
- Writing: human first. Second person, short paragraphs, 1–3 word titles (verbs for guides, nouns for concepts), a `description` in every frontmatter, a "Check it worked" or "Next" section at the end of guides and concepts.
- Runtime selector: only on guide pages. Explain nothing there that belongs in a concept page. Use the globally registered MDX components (no import needed), each `<Runtime>` on its own lines:

  ```mdx
  <RuntimeTabs skills={["serve-agent-endpoints"]}>
  <Runtime value="agent-node">

  Steps with the 6022 Agent…

  </Runtime>
  <Runtime value="skills">

  Steps that work for any runtime today…

  </Runtime>
  </RuntimeTabs>
  ```

  Every runtime selector takes exactly two blocks: `agent-node` and `skills`; anything else fails the build. Don't open them with a "With the…" line, the tab already names the runtime. Runtimes are declared in `src/components/RuntimeTabs/runtimes.ts`. Hermes, OpenClaw and "Other agents" have status `skills`: their tab shows a note linking the agent skills listed in `skills` and the runtime's setup page, then the shared `skills` block. When the skills don't cover a step, say so at the top of the `skills` block. Marking a runtime `available` makes every runtime selector require its own block. The choice is shared by every runtime selector and kept in `?runtime=`.
- Moved pages: add the old path to the `plugin-client-redirects` list in [docusaurus.config.ts](docusaurus.config.ts); the agent skills link to the docs.
- Graphic chart: tokens live in `src/css/custom.css` (site) and `videos/src/kit.tsx` (videos). Teal accent `#1a7a66` on light, `#25c2a0` on dark; neutral greys from the 6022 Agent console; Geist and Geist Mono; 10px radius. Reuse them rather than adding colours.
- Diagrams: use Mermaid code blocks (```mermaid), not images: they stay readable as text in `llms.txt` for agents. Use them for flows and structures (sequence diagrams for exchanges, flowcharts for architecture). Keep labels short, avoid `#` and `"` inside sequence messages.
- Videos: Remotion sources in `videos/` (own `package.json`), renders in `static/video/`, embedded with `<Video name="…" caption="…" />`. See `videos/README.md`.
- Assets: place under `static/` and reference as `/img/...` etc.
- Do not introduce mixed package managers. Keep one lockfile per npm project (the site, and `videos/`).
